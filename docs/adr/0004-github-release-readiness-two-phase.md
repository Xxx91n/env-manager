# GitHub Public Release Readiness — Two-Phase Strategy

Decided to split the GitHub public release into two phases. Phase 1 (Local) covers all artifacts producible within the local codebase: community health files (Contributor Covenant v2.1 COC, self-written CONTRIBUTING.md, GitHub SECURITY.md, Issue/PR templates), README.md + README_CN.md rewrite per standard-readme spec with v0.8-v0.9.11 feature sync and screenshot placeholders, Tauri capability coverage audit, CSP `'unsafe-inline'` removal test, Named Pipe DACL hardening, and README unsigned-code warning. Phase 2 (Remote) covers artifacts requiring external service interaction after the repository goes public: winget manifest submission to `microsoft/winget-pkgs`, Authenticode code signing (OV certificate), and Tauri updater plugin integration. Phase 2 is blocked until repository visibility switches from private to public. Rationale: the project has no existing public users and is still in active development; deferring remote-push work avoids premature external dependencies while ensuring the local codebase is fully presentable when the switch happens.
