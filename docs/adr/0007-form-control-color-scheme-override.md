# Form controls override :root color-scheme to follow app theme, not system

`:root` declares `color-scheme: light dark` (v0.9.24 hard boundary) so WebView2 native scrollbars follow the app theme. But this inherits to all elements, making native form controls (radio, checkbox, select, input focus outline) follow the Windows system `prefers-color-scheme` instead of the app `data-theme`. We override at the form-control element level: `input, select, textarea { color-scheme: light; }` + `input[type="radio"], input[type="checkbox"] { accent-color: hsl(var(--primary)); }` + `input:focus, select:focus, textarea:focus { outline: none; }`. This binds form control fill/outline to app theme variables while leaving the scrollbar (which only reads :root) following `data-theme`. Rejected: changing `:root` to `color-scheme: light` and setting `color-scheme: dark` only inside `[data-theme="dark"]` (would regress the v0.9.24 scrollbar hard boundary). Rejected: `appearance: none` custom radio/checkbox (15+ lines CSS per control, high maintenance for no user-facing gain over accent-color).
